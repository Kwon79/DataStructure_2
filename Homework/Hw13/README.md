# 과제 13: 병합 정렬과 퀵 정렬의 성능 비교

## 1. 실험 방법

- **비교 횟수**: 병합 정렬은 병합 과정의 값 비교, 퀵 정렬은 분할 중 데이터와 피벗의 비교 + Median-of-Three의 중앙값 결정 비교. 인덱스/종료 조건 검사, 난수 생성, 데이터 이동은 제외
- **실행시간**: 정렬 시작부터 완료까지(배열 복사, 검증, 출력 제외)를 `QueryPerformanceCounter`로 ms 단위 측정. 시간이 매우 짧아서 한 번 실행 안에서 같은 정렬을 100회 반복한 평균을 사용. 병합 정렬의 임시 배열 할당/해제는 알고리즘의 일부라서 시간에 포함
- **메모리**
- 무작위 데이터와 Random 피벗 때문에 실행마다 값이 달라지므로, 프로그램을 **5회 실행한 평균**을 분석에 사용 (5회 실행 화면은 첨부 이미지 참고)

## 3. 메모리 측정 방법과 계산 기준

프로파일링 도구로 측정하지 않고, 정렬이 사용하는 추가 공간을 **직접 계산**했다.

- 병합 정렬 = 임시 배열 + 재귀 호출 스택 = `n × 4B + 재귀 최대 깊이 × 44B`
- 퀵 정렬 = 재귀 호출 스택 = `재귀 최대 깊이 × 40B` (별도 배열 없음)
- **호출 1회의 크기** = 반환 주소 + 매개변수 + 지역변수의 크기 합 (x64 기준)
  - 병합 정렬 `ms_rec`: 포인터 4개(반환 주소, arr, tmp, ctx) 32B + int 3개(low, high, mid) 12B = **44B**
  - 퀵 정렬 `qs_rec`: 포인터 3개(반환 주소, arr, ctx) 24B + int 3개 12B + enum 4B = **40B**
- **재귀 최대 깊이**는 정렬 중 실제로 센 값이다(함수 진입 시 +1, 반환 시 -1, 그중 최댓값).
- 계산 예: n=1,000 병합 정렬은 임시 배열 4,000B + 깊이 11 × 44B = 484B → **4,484B**. n=20,000은 80,000B + 깊이 16 × 44B = 704B → **80,704B**
- 제외한 것: 원본 데이터 배열(공통 비용), 깊이와 상관없이 일정 크기만 쓰는 `partition`/`merge`/`swap` 호출의 스택, 스택 패딩과 레지스터 저장 공간
- 병합 정렬은 깊이가 항상 ⌈log₂n⌉+1로 정해져 있어서 값이 매번 같고, 퀵 정렬은 분할이 얼마나 균형 있게 되느냐에 따라 깊이가 달라져서 실행마다 값이 다르다.

## 4. 비교·분석

### 4.1 데이터 크기에 따른 비교 횟수 변화

- 모든 정렬에서 n이 2배가 될 때 비교 횟수가 약 2.1~2.3배로 늘었다. n이 정확히 2배가 아니라 조금 더 크게 늘어나는 O(n log n) 패턴이다.
- **병합 정렬이 모든 크기에서, 5번 모두 가장 적게 비교했다.** 퀵 정렬 중 가장 적은 값과 비교해도 약 20% 적었다(20,000개: 260,839 vs 330,663). n·log₂n 대비로 보면 병합은 0.87~0.91배, 퀵 Median3는 1.10~1.16배, First는 1.19~1.25배였다.
- **이유**: 병합 정렬은 항상 정확히 절반으로 나누므로 깊이가 log n으로 고정이고, 병합 1회의 비교는 구간 길이 - 1번을 넘지 않는다. 퀵 정렬은 피벗이 구간의 중앙값에서 벗어나면 한쪽 구간이 커져서 깊이가 늘고 비교가 늘어난다. 평균적으로 퀵 정렬은 약 1.39·n·log₂n(저차항 때문에 실측치는 이보다 작다), 병합 정렬은 약 n·log₂n − n번이다.
- 병합 정렬의 비교 횟수는 데이터가 달라도 거의 같았다(20,000개 5회: 260,749~260,923). 반면 퀵 First는 331,891~382,547로 크게 흔들렸다. 퀵 정렬의 비교 횟수는 데이터와 피벗에 따라 달라지기 때문이다.

### 4.2 실행시간 차이

- 평균 시간은 **퀵 First ≈ 퀵 Median3 < 병합 < 퀵 Random** 순이었다. 병합 정렬은 퀵 First/Median3보다 모든 크기에서 평균 2~38% 오래 걸렸다.
- **비교 횟수는 병합이 적은데 시간은 더 걸린 이유**: 병합 정렬은 병합할 때마다 값을 임시 배열에 옮겼다가 다시 원래 배열로 복사하고(데이터 이동이 많음), 임시 배열 할당/해제도 해야 한다. 퀵 정렬은 제자리에서 교환만 하므로 이동 비용이 적다. 시간은 비교 횟수뿐 아니라 데이터 이동량에도 영향을 받는다.
- **Random이 가장 느린 이유**: 비교 횟수는 First와 비슷한데 시간은 약 1.3~2.9배 걸렸다. 분할할 때마다 `rand()`를 호출하는 비용이 실행시간에 포함되는 것이 한 가지 이유다(난수 생성은 비교 횟수에는 안 세지만 시간에는 들어간다).
- n=1,000처럼 시간이 0.1 ms 안팎으로 짧을 때는 측정 오차의 영향이 크고, Debug 빌드 결과라서 Release에서는 값이 달라질 수 있다.

### 4.3 메모리 사용량 차이

- 병합 정렬은 n이 2배가 되면 메모리도 약 2배(1.9~2.0배)가 됐다. 80,704B 중 80,000B가 임시 배열이다. n이 20배(1,000→20,000)가 될 때 병합은 약 18배, 퀵은 약 1.6배(880→1,392B) 늘었다.
- 퀵 정렬은 1KB 안팎이고 n이 2배가 되어도 1.0~1.2배만 늘었다. 별도 배열이 없고 재귀 호출 스택만 쓰는데, 깊이가 log n 수준으로만 늘기 때문이다. 20,000개에서 병합은 퀵의 약 58~77배를 썼다.
- 퀵 정렬 중에서는 Median3가 약 25% 적게 썼다(648~1,048B). 분할이 더 균형 있게 되어 재귀 깊이가 약 16~26단계로, First(약 22~35단계)보다 얕기 때문이다.

### 4.4 퀵 정렬의 피벗 선택 방법에 따른 차이

- **비교 횟수**: Median3가 모든 크기에서 가장 적었다. First보다 5~9%, Random보다 1~7% 적었다(8,000개 이상에서는 First보다 5번 모두 적었다). Random은 First보다 6개 크기 중 5개에서 적었지만(4,000개만 많음) 차이는 Median3보다 작았다.
- **실행시간**: First와 Median3가 비슷하게 빨랐고, Random이 가장 느렸다.
- **메모리**: Median3가 가장 적었다.
- **이유**: 세 값의 중앙값을 고르면 구간의 최솟값/최댓값 근처가 피벗이 될 확률이 낮아서 분할이 균형 있게 된다. 그래서 재귀 깊이가 얕아지고, 비교 횟수와 스택 메모리가 같이 줄었다. 데이터가 무작위라서 First의 첫 원소도 이미 무작위 값과 비슷하므로 Random을 써도 분할 균형이 크게 좋아지지 않았고, 대신 난수 생성 비용이 추가됐다.
- 이번 실험에서는 **Median3가 가장 효과적**이었다.

### 4.5 시간 복잡도와 공간 복잡도 차이

| | 병합 정렬 | 퀵 정렬 |
|---|---|---|
| 시간 복잡도 (최선/평균) | O(n log n) / O(n log n) | O(n log n) / O(n log n) |
| 시간 복잡도 (최악) | O(n log n) | O(n²) |
| 공간 복잡도 | O(n) (임시 배열) | 평균 O(log n), 최악 O(n) (호출 스택) |

- 병합 정렬은 항상 절반으로 나누므로 어떤 입력에서도 O(n log n)이고, 임시 배열이 필요해서 공간이 O(n)이다. 실험에서도 병합 메모리가 n에 비례해 늘었고, 비교 횟수는 매번 거의 같았다.
- 퀵 정렬은 평균적으로 O(n log n)이지만 피벗이 계속 극단적인 값이면 O(n²)이 될 수 있다. 별도 배열이 없어서 공간은 호출 스택(평균 O(log n))뿐이다. 이번 데이터는 무작위라서 최악의 경우는 나타나지 않았다. 이미 정렬된 데이터에서 First 피벗이 최악이 되는 것은 이번에 측정하지 않은 이론적 설명이다.

## 5. 결론

1. **비교 횟수**는 병합 정렬이 가장 적었고(퀵 최소 대비 약 20% 적음), 퀵 정렬에서는 Median3가 가장 적었다.
2. **실행시간**은 퀵 First/Median3가 가장 빨랐고 병합 정렬이 그다음이었다. 병합 정렬은 비교는 적지만 임시 배열로의 데이터 이동 비용이 더 컸고, Random은 난수 생성 비용 등이 더해져 가장 느렸다.
3. **메모리**는 퀵 정렬이 압도적으로 적었다(20,000개에서 병합이 약 58~77배). 병합 정렬은 n에 비례하는 임시 배열이 필요하다.
4. 종합하면, 이번 실험에서는 **Median3 퀵 정렬이 시간과 메모리 모두 가장 효율적**이었고, 병합 정렬은 비교 횟수가 적고 입력에 상관없이 성능이 일정하다는 장점이 있지만 메모리를 많이 쓴다.
