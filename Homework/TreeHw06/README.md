# 과제 06: 순차 탐색, 이진 탐색 트리와 AVL 트리의 성능 비교
  
## 1. 파일 구성
 
| 파일 | 내용 |
|---|---|
| `AVL.h` | BSTNode, AVLNode 구조체 및 함수 선언 |
| `AVL.c` | BST / AVL 생성·삽입·탐색·높이·회전, 순차 탐색 구현 |
| `main.c` | 데이터 생성, 삽입, 탐색 실행, 결과 출력 |

## 2. 구현 방식
 
- 0~1,000 사이의 난수를 100번 생성하고, **같은 난수를 같은 순서로** 배열, BST, AVL 트리에 처리합니다.
- **배열**: 새 값이 생성될 때마다 순차 탐색으로 중복 여부를 확인하고, 중복이 아니면 배열 끝에 추가합니다. 정렬하지 않습니다.
- **BST**: 루트부터 비교하며 작으면 왼쪽, 크면 오른쪽으로 내려가 삽입합니다. 같은 값을 만나면 삽입하지 않습니다.
- **AVL 트리**: BST와 같은 방식으로 삽입한 뒤, 되돌아오며 각 노드의 높이를 갱신하고 균형 계수(왼쪽 높이 − 오른쪽 높이)가 ±1을 벗어나면 LL, RR, LR, RL 회전으로 균형을 복구합니다. 같은 값을 만나면 삽입하지 않습니다.
- 두 트리 모두 포인터로 연결한 구조로 구현했습니다.
- 삽입이 끝난 뒤 0~1,000 사이의 탐색 키 50개를 생성하고, 각 키마다 세 가지 탐색을 모두 수행합니다.
### 비교 횟수 기준
 
- 배열: 중복 확인을 위한 순차 탐색에서 원소와 비교한 횟수
- BST / AVL: 삽입 위치 또는 중복 값을 찾기 위해 기존 노드와 비교한 횟수
- **중복으로 판정되어 삽입하지 않은 경우의 비교도 포함**합니다.
- AVL의 높이 계산, 균형 계수 확인, 회전 여부 판단은 비교 횟수에 포함하지 않습니다.
- 트리의 높이는 노드 수 기준입니다. (빈 트리 0, 루트만 있으면 1)

## 4. 분석
 
### 4-1. BST와 AVL 트리의 높이가 서로 다른 이유
 
이번 실행에서 BST의 높이는 11, AVL 트리의 높이는 8였습니다. 저장된 값은 두 트리가 완전히 같은데도 높이가 다른 이유는 **삽입 과정에서 균형을 맞추는지 여부**가 다르기 때문입니다.
 
- **BST**는 값이 들어온 순서대로 위치만 찾아 붙일 뿐 구조를 바꾸지 않습니다. 따라서 어떤 순서로 들어오느냐에 따라 한쪽 가지만 길어질 수 있고, 높이는 입력 순서에 좌우됩니다.
- **AVL 트리**는 삽입할 때마다 각 노드의 왼쪽과 오른쪽 서브트리의 높이 차가 1을 넘지 않도록 회전합니다. 그래서 한쪽으로 길어지려는 순간 구조가 재배치되어, 노드 수 n에 대해 높이가 항상 log₂n에 가까운 값으로 유지됩니다.
노드가 약 100개일 때 이론적으로 가능한 가장 낮은 높이는 7이고, AVL 트리는 이에 가까운 값(최대 8~9 정도) 안에서만 움직입니다. 반면 BST는 이론상 한쪽으로만 자라면 100까지 커질 수 있습니다. 
 
### 4-2. 트리의 높이가 탐색 비교 횟수에 미치는 영향
 <img width="502" height="1024" alt="image" src="https://github.com/user-attachments/assets/fe45f842-03b4-4e9e-8640-cf0326620ef9" />

BST와 AVL의 탐색은 방법이 같아서, 비교 횟수는 루트에서 키가 있을 법한 자리까지 내려가는 **깊이**에 의해 결정됩니다. 한 번 탐색할 때 비교 횟수는 아무리 많아도 트리의 높이를 넘을 수 없습니다.
 
실행 결과 BST 탐색의 평균 비교 횟수는 7.78회, AVL 탐색은 6.78회였습니다. 높이가 11(BST)에서 8(AVL)로 낮아지면서 평균 비교 횟수가 1회 줄었습니다.
 
순차 탐색은 트리 구조와 상관없이 배열을 앞에서부터 확인하므로, 키가 없는 경우에는 항상 배열 전체(97회)를 비교합니다. 이번 실험에서 탐색 키 50개 중 45개가 실패였고, 이 때문에 순차 탐색의 평균이 89.82회로 배열 길이에 가까웠습니다. 트리 탐색은 배열 크기가 아니라 높이에 비례하므로 두 방법 사이에 큰 차이가 생겼습니다.
 
### 4-3. 세 자료구조의 생성 비용과 탐색 비용 비교
 
**생성 비용**
 
- **배열**은 저장 자체에는 비교가 필요 없지만, 이번 과제는 중복을 막기 위해 새 값이 들어올 때마다 지금까지 저장된 모든 값과 비교해야 합니다. 그 결과 생성 비교 횟수가 4726회로 세 자료구조 중 가장 컸습니다. 저장된 값이 늘수록 한 번의 확인 비용도 늘어나므로 n이 커질수록 비용이 n²에 가깝게 증가합니다.
- **BST**는 트리를 따라 내려가며 비교하므로 새 값 하나당 비교 횟수가 현재 깊이에 비례하여 생성 비교 횟수가 551회였습니다.
- **AVL 트리**는 530회였습니다. BST와 비교하면 21회 적었습니다. AVL은 트리를 낮게 유지하기 때문에 이후 삽입에서 내려가는 깊이가 짧아져 비교 횟수가 BST보다 적은 경향이 있습니다. 다만 회전에 드는 작업은 이 비교 횟수에 포함하지 않았으므로 실제 처리 비용은 이 값보다 클 수 있습니다.
**탐색 비용**
 
세 방법의 탐색 총 비교 횟수는 순차 탐색 4491회, BST 389회, AVL 339회였습니다. 트리 두 가지가 순차 탐색보다 훨씬 적었고, AVL이 BST보다 적었습니다.
 
**생성 + 탐색 합계**
 
생성 비용과 탐색 비용을 합치면 배열 9217회, BST 940회, AVL 869회였습니다. 이번 실험에서는 AVL이 가장 적었습니다.
 
### 4-4. 여러 번 실행했을 때의 경향 
 
난수를 사용하므로 실행할 때마다 값이 달라질 수 있어서, 여러 번 실행한 결과를 함께 적습니다.
 
| 실행 | 저장된 값 수 | BST 높이 | AVL 높이 | BST 탐색 평균 | AVL 탐색 평균 |
|---|---|---|---|---|---|
| 1 | 98개 | 15 | 8 | 8.34회 | 6.54회 |
| 2 | 96개 | 12 | 8 | 8.30회 | 6.66회 |
| 3 | 93개 | 12 | 8 | 7.88회 | 6.58회 |

 - 실행마다 BST의 결과는 12~15사이를 왔다갔다하였으며 AVL의 높이는 8로 거의 일정한 모습을 계속하여 보여주었습니다. 
 
## 5. 결론
 
- 100번의 난수 중 97개가 서로 다른 값으로 저장되었고, 세 자료구조에 같은 값이 저장되었습니다.
- AVL 트리는 회전으로 균형을 유지해 높이가 8로 BST(11)보다 낮았고, 그 결과 탐색 평균 비교 횟수가 6.78회(AVL)와 7.78회(BST)로 AVL이 낮았습니다.
- 순차 탐색은 평균 89.82회로, 두 트리 탐색보다 훨씬 많은 비교가 필요했습니다.
- 다만 이번 실험처럼 무작위로 삽입하면 BST도 어느 정도 균형이 잡혀서 AVL과의 차이는 크지 않았습니다. 정렬된 순서로 삽입하면 BST의 높이는 노드 수만큼 커지지만 AVL은 그대로 log₂n 수준을 유지하므로, **입력 순서에 상관없이 일정한 성능을 보장한다는 점**이 AVL의 장점입니다.
