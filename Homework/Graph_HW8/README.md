# 과제 08: 최소 비용 신장 트리 알고리즘 비교

## 1. 개요

정점 50개인 가중치 무방향 단순 연결 그래프를 **희소 그래프(간선 100개)** 와 **밀집 그래프(간선 600개)** 로 랜덤 생성하고,
**인접 리스트 + Kruskal 알고리즘**과 **인접 행렬 + Prim 알고리즘**으로 최소 비용 신장 트리(MST)를 구했다.
각 경우의 메모리 사용량과 실행시간을 측정하여 그래프의 밀도, 표현 방법, MST 알고리즘에 따른 차이를 분석했다.
희소 그래프는 Case 1과 3이, 밀집 그래프는 Case 2와 4가 정점·간선·가중치가 모두 같은 동일한 그래프를 사용한다.

| | 정점 수 | 간선 수 |
|---|---|---|
| 희소 그래프 | 50 | 100 |
| 밀집 그래프 | 50 | 600 |

## 2. 파일 구성

| 파일 | 내용 |
|---|---|
| `mst.h` | 상수, 구조체(`edge`, `listNode`, `listGraph`, `matrixGraph`), 함수 선언 |
| `mst.c` | 랜덤 그래프 생성, 인접 리스트 / 인접 행렬 구현, Kruskal / Prim 알고리즘, 메모리 계산, 출력 |
| `main.c` | 희소/밀집 그래프 생성, 4가지 케이스 실행 및 시간 측정, 결과 출력 |


## 3. 구현 및 측정 방법

### 3-1. 그래프 생성

- 정점 번호는 0부터 49까지이고, 자기 자신을 잇는 간선과 중복 간선은 만들지 않는다. 가중치는 1부터 100 사이의 랜덤 양의 정수이다.
- **연결 그래프 보장**: 간선 49개짜리 트리(정점 i를 0부터 i-1 사이의 임의의 정점에 연결)를 먼저 만든 뒤 나머지 간선을 랜덤으로 채운다. 그리고 DFS로 모든 정점이 연결되어 있는지 한 번 더 확인하고, 연결되지 않았다면 다시 생성한다.
- 간선 목록을 한 번만 만들고 같은 목록으로 인접 리스트와 인접 행렬을 모두 구성해서 두 표현이 완전히 같은 그래프가 된다.

### 3-2. MST 알고리즘

- **Kruskal (인접 리스트)**: 리스트를 돌며 모든 간선을 배열로 모으고(무방향이라 두 번 저장된 간선은 한 번만), 가중치 오름차순으로 정렬(`qsort`)한 뒤, Union-Find로 사이클이 생기지 않는 간선만 추가한다. 간선이 49개가 되면 멈춘다.
- **Prim (인접 행렬)**: 0번 정점에서 시작해 `visited`, `dist`(MST와 연결되는 최소 비용), `from`(그 간선의 MST쪽 끝 정점) 배열을 이용한다. MST에 포함되지 않은 정점 중 `dist`가 가장 작은 정점을 고르고, 행렬의 해당 행을 보며 `dist`를 갱신하는 과정을 정점 수만큼 반복한다.

### 3-3. 메모리 사용량 (Byte)
`sizeof`로 계산했고, 그래프 표현과 알고리즘의 보조 자료구조, MST 결과 배열을 모두 합했다. 난수 생성용 임시 배열과 `malloc` 내부 관리 영역은 제외했다.

| 항목 | 크기 |
|---|---|
| 인접 리스트 구조체 (`n`, `e`, 헤드 포인터 50개) | 408B |
| 리스트 노드 (`vertex` 4B + `weight` 4B + `link` 8B), 간선 1개당 2개 | 16B x 2 |
| Kruskal의 간선 배열 (`edge` 12B), 간선 1개당 1개 | 12B |
| Kruskal의 Union-Find `parent` 배열 | 200B |
| 인접 행렬 구조체 (`n`, `e`, 50 x 50 가중치 행렬) | 10,008B |
| Prim의 `visited`, `dist`, `from` 배열 | 600B |
| MST 결과 배열 (`edge` 49개) | 588B |

- 인접 리스트 + Kruskal = 408 + (간선 수 x 32) + (간선 수 x 12) + 200 + 588 = 1,196 + 44 x 간선 수
- 인접 행렬 + Prim = 10,008 + 600 + 588 = 11,196 (간선 수와 무관)

### 3-4. 실행시간

그래프 생성이 끝난 뒤 MST 알고리즘을 시작할 때부터 MST 계산이 끝날 때까지를 `clock()`으로 측정했다. 그래프 생성과 출력은 포함하지 않았다.
정점이 50개뿐이라 MST를 한 번 구하는 시간이 `clock()`의 정밀도(약 1ms)보다 훨씬 짧아서, **1,000번 반복 실행한 전체 시간을 재고 1번당 평균(ms)** 을 구했다.
Kruskal은 간선 모으기, 정렬, Union-Find를 모두 포함한 시간이고, Prim은 `dist` 배열 초기화부터 MST 완성까지의 시간이다. 4가지 경우 모두 같은 방법과 단위를 사용했다.

## 5. 분석

### 5-1. MST 전체 비용과 간선 수

- 정점이 50개인 연결 그래프의 MST는 정점 수 - 1 = 49개의 간선으로 이루어지는데, 4가지 경우 모두 49개로 나와서 올바르게 구해졌다.
- 같은 그래프에서는 Kruskal과 Prim의 비용이 같았다. MST의 비용은 하나로 정해지지만 가중치가 같은 간선이 여러 개 있으면 두 알고리즘이 서로 다른 간선을 고를 수 있어서 간선 구성만 다를 수 있다.
- **희소 그래프의 비용(1,545)이 밀집 그래프(305)보다 5배 이상 컸다.** 가중치가 1부터 100 사이의 랜덤이라, 간선이 600개이면 정점마다 가중치가 작은 간선을 고를 후보가 많아서 MST 간선의 평균 가중치가 약 6(305 / 49)으로 낮아진다. 간선이 100개뿐인 희소 그래프는 후보가 적어서 가중치가 큰 간선도 MST에 들어가야 하고 평균이 약 32(1,545 / 49)가 되었다. 희소 그래프는 49개 간선이 전체 간선의 약 절반을 차지하는 반면, 밀집 그래프는 600개 중 49개(약 8%)만 고르는 셈이다.

### 5-2. 메모리 사용량

- **인접 행렬 + Prim은 간선 수와 상관없이 11,196B로 같았다.** 50 x 50 행렬(10,008B)이 항상 같은 크기이고 보조 배열도 정점 수에만 비례하기 때문이다.
- **인접 리스트 + Kruskal은 간선 수에 비례해서 늘었다.** 희소 그래프는 5,596B, 밀집 그래프는 27,596B로, 간선이 6배 늘자 메모리가 약 4.9배가 되었다. 간선 하나당 리스트 노드 2개(32B)와 Kruskal의 간선 배열(12B)로 44B씩 들기 때문이다.

| 구성 | Case 1 (희소 - 리스트) | Case 2 (밀집 - 리스트) | Case 3, 4 (행렬) |
|---|---:|---:|---:|
| 그래프 표현 | 408 + 3,200 = 3,608 | 408 + 19,200 = 19,608 | 10,008 |
| Kruskal의 간선 배열 | 1,200 | 7,200 | - |
| Union-Find / Prim 보조 배열 | 200 | 200 | 600 |
| MST 결과 배열 | 588 | 588 | 588 |
| 합계 | 5,596 | 27,596 | 11,196 |

- 희소 그래프에서는 리스트 쪽이 행렬의 약 절반(5,596B vs 11,196B)이고, 밀집 그래프에서는 리스트 쪽이 약 2.5배(27,596B vs 11,196B)였다.
- 계산상 `1,196 + 44 x 간선 수 = 11,196`이 되는 간선 약 227개(최대 간선 1,225개의 약 19%)가 넘으면 리스트 + Kruskal이 행렬 + Prim보다 메모리를 더 쓴다.

### 5-3. 실행시간

- Case 1은 0.0080ms, Case 2는 0.0530ms, Case 3은 0.0090ms, Case 4는 0.0100ms였다 (각각 8.0, 53.0, 9.0, 10.0 마이크로초).
- **Kruskal은 간선 수가 늘자 시간이 약 6.6배(0.0080 → 0.0530ms) 늘었고, Prim은 거의 그대로(0.0090 → 0.0100ms)였다.**
- 희소 그래프에서는 두 알고리즘의 시간이 거의 같았다(0.0080ms vs 0.0090ms). 1,000번 반복한 전체 시간이 8ms와 9ms로 `clock()`의 정밀도(1ms)와 같은 크기의 차이라서, 이 차이만으로는 어느 쪽이 빠르다고 말할 수 없다.
- 밀집 그래프에서는 Prim(0.0100ms)이 Kruskal(0.0530ms)보다 약 5.3배 빨랐다. 반복한 전체 시간이 10ms와 53ms로 차이가 분명하다.
- 이번 측정은 Debug 빌드 기준이라 Release보다 절대 시간이 길 수 있지만, 같은 조건에서 비교한 것이므로 상대적인 경향은 유효하다.

### 5-4. 희소 그래프와 밀집 그래프에서의 성능 차이

- **메모리**: 희소 그래프에서는 리스트 방식이 행렬 방식보다 작고, 밀집 그래프에서는 리스트 방식이 더 크다. 행렬은 밀도와 상관없이 고정이다.
- **실행시간**: 희소 그래프에서는 Kruskal과 Prim이 거의 비슷하고, 밀집 그래프에서는 Prim이 훨씬 빠르다. 그래프가 밀집할수록 Kruskal만 느려졌다.
- 같은 정점 수라도 간선 수가 늘면 Kruskal은 정렬할 간선이 많아져서 메모리와 시간이 모두 늘지만, Prim은 행렬 크기가 정점 수로 정해져 있어 영향을 거의 받지 않는다.

### 5-5. 인접 리스트와 인접 행렬의 메모리 사용 차이

- 행렬은 간선이 있든 없든 50 x 50칸을 모두 잡아 두므로, 희소 그래프에서는 대부분의 칸이 `INF`(간선 없음)로 낭비된다. 반면 간선이 많은 밀집 그래프에서는 칸이 많이 채워져서 낭비가 적다.
- 리스트는 존재하는 간선만 노드로 저장해서 간선이 적으면 작지만, 노드마다 포인터(8B)와 패딩이 붙어서 간선 하나를 저장하는 비용이 행렬의 칸(4B)보다 훨씬 크다. 그래서 간선이 많아지면 행렬보다 커진다.
- 이번 실험에서는 그래프 표현만 비교해도 희소 그래프는 리스트 3,608B vs 행렬 10,008B, 밀집 그래프는 리스트 19,608B vs 행렬 10,008B로 같은 경향이 나타났다.

### 5-6. Kruskal 알고리즘과 Prim 알고리즘의 실행 특성 차이

| | Kruskal (인접 리스트) | Prim (인접 행렬) |
|---|---|---|
| 방식 | 간선을 정렬해서 작은 것부터 사이클이 없으면 추가 | 정점 하나에서 시작해 트리를 한 정점씩 확장 |
| 시간이 좌우되는 요소 | 간선 수 E (정렬 E log E) | 정점 수 V (V x V 반복) |
| 추가로 필요한 메모리 | 간선 배열(간선 수에 비례) + Union-Find | visited, dist, from 배열(정점 수에 비례) |
| 이번 실험 결과 | 간선이 6배 늘자 시간 6.6배, 메모리 4.9배 | 간선이 6배 늘어도 시간 1.1배, 메모리 변화 없음 |

- Kruskal은 정점 수와 상관없이 간선 수만큼의 정렬이 필요해서 간선이 늘수록 시간이 늘었다. 이번 실험에서 간선 수 100개일 때 `E log E`는 약 660, 600개일 때는 약 5,500으로 약 8.3배 차이가 나는데, 측정된 증가폭(약 6.6배)과 비슷한 수준이다. 한편 간선이 600개여도 MST 간선 49개가 정해지면 멈추기 때문에 정렬 뒤의 확인은 일부만 하지만, 간선을 모으고 정렬하는 비용은 줄일 수 없다.
- Prim은 정점마다 `dist`가 가장 작은 정점을 찾고(50칸) 행을 훑어 갱신(50칸)하는 과정을 50번 반복하므로 약 50 x 50 = 2,500회 수준으로, 간선이 몇 개든 같다. 실험에서도 시간이 거의 일정했다. 밀집 그래프의 Prim이 약간 느린 것(0.0090 → 0.0100ms)은 간선이 많아 `dist` 갱신이 더 자주 일어났기 때문일 수 있지만, 측정 정밀도를 생각하면 오차 범위 안이다.
- 간선 100개일 때는 `E log E`(약 660)가 `V x V`(2,500)보다 작아서 이론상 Kruskal이 유리하지만, 실제로는 간선 모으기, `malloc`, `qsort`의 함수 호출 같은 상수 비용이 있어서 Prim과 비슷한 시간이 나왔다.

### 5-7. 그래프 밀도가 각 방법의 성능에 미치는 영향

- 밀도가 높아지면 **리스트 + Kruskal은 메모리(약 4.9배)와 시간(약 6.6배)이 모두 늘었고**, **행렬 + Prim은 둘 다 거의 변하지 않았다.** 리스트 + Kruskal의 비용이 간선 수에 비례하고 행렬 + Prim의 비용이 정점 수에 비례하기 때문이다.
- 그래서 희소할 때는 리스트 + Kruskal이 메모리에서 이득이고 시간은 비슷하며, 밀집할 때는 행렬 + Prim이 메모리와 시간 모두 유리하다.
- 같은 정점 수에서도 밀도에 따라 MST 비용이 달라진 것(1,545와 305)은 알고리즘이 아니라 그래프 자체의 성질이지만, 간선이 많을수록 가중치가 작은 간선을 고를 수 있다는 점은 확인할 수 있었다.

### 5-8. 어떤 경우에 무엇을 사용하는 것이 적절한가

| 상황 | 적절한 방법 | 근거 (이번 실험) |
|---|---|---|
| 간선이 적은 희소 그래프 | 인접 리스트 + Kruskal | 메모리가 행렬의 절반 (5,596B vs 11,196B), 시간은 비슷 (0.0080ms vs 0.0090ms) |
| 간선이 많은 밀집 그래프 | 인접 행렬 + Prim | 메모리가 약 2.5배 작고 (11,196B vs 27,596B), 시간도 약 5.3배 빠름 (0.0100ms vs 0.0530ms) |
| 간선 수가 계속 늘어날 수 있는 경우 | 인접 행렬 + Prim | 비용이 간선 수와 무관하게 정점 수로 정해짐 |

## 6. 결론

Kruskal 알고리즘은 간선을 정렬하는 방식이라 비용이 간선 수에 비례하고, Prim 알고리즘은 인접 행렬로 정점을 확장하는 방식이라 비용이 정점 수에 비례한다.
따라서 그래프가 희소할 때는 인접 리스트 + Kruskal이 메모리 면에서 유리하고 속도는 Prim과 비슷하며, 밀집할수록 인접 행렬 + Prim이 메모리와 속도 모두에서 유리했다.
이번 실험은 한 번 실행한 결과이고 그래프가 랜덤으로 만들어지므로 숫자는 실행마다 달라질 수 있지만, 간선 수에 따른 경향은 같게 나타난다.
