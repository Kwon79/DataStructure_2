# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

선택 정렬, 버블 정렬(일반 / 조기 종료), 삽입 정렬(`>` / `>=`)을 C로 직접 구현하고, 같은 입력에 대해 **숫자 비교 횟수**, **데이터 이동 횟수**, **안정성**을 측정해 비교했다. 아래의 모든 숫자는 실제 프로그램 실행 결과이다.

## 0. 구성 및 실행 환경

| 파일 | 역할 |
|---|---|
| `sort.h` | 상수, `Data` 구조체, 카운터와 `MOVE` 매크로, 함수 선언 |
| `sort.c` | 정렬 알고리즘 구현, 난수/검증 유틸, 실험 및 출력 |
| `main.c` | `run_all_experiments()` 호출 |

## 1. 실험 방법

**데이터.** `(key1, key2, order)` 구조체 10,000개를 사용했다. key1, key2는 0~1,000,000 범위에서 독립적으로 뽑은 난수이고, `order`는 원래 입력 순번이다. `order`는 정렬 기준이 아니라 **안정성 검증을 위해서만** 저장했다.

**비교 횟수.** 정렬 순서를 결정하려고 두 데이터의 key1을 비교하는 `if`가 실행될 때마다 1씩 센다. `for`문의 인덱스 비교나 `swapped` 검사 같은 반복 제어용 비교는 세지 않았다.

**이동 횟수.** 구조체 하나를 통째로 대입(복사)하면 1회로 센다 (`MOVE` 매크로). 두 데이터를 교환하면 `temp = a; a = b; b = temp;`이므로 3회이다. 삽입 정렬은 임시 변수에 저장(1회), 한 칸씩 밀기(1회씩), 최종 위치에 대입(1회)을 각각 센다. 선택 정렬은 최솟값 위치가 현재 위치와 같으면 교환하지 않는다.

**제외한 연산.** 원본 배열 복사, 데이터 생성, 정렬/역순/부분 정렬 입력을 만들기 위한 사전 정렬(`qsort`)은 비교·이동 횟수에 포함하지 않았다. 정렬 알고리즘 자체는 라이브러리 함수를 쓰지 않고 직접 구현했다.

**공정한 비교.** 한 번의 시행에서 만든 원본 배열을 네 알고리즘(선택, 버블, 조기 종료 버블, 삽입)이 각각 복사해서 사용한다. 따라서 모든 알고리즘이 똑같은 난수 데이터를 정렬한다. 정렬이 끝날 때마다 key1이 오름차순인지 검사했고, 모든 경우 `YES`였다.

## 2. 무작위 데이터 100회 실험

시행마다 새 난수 10,000개를 만들고 네 알고리즘을 돌렸다 (총 100회).

| 알고리즘 | 총 비교 횟수 | 평균 비교 횟수 | 평균 이동 횟수 |
|---|---:|---:|---:|
| 선택 정렬 | 4,999,500,000 | 49,995,000.00 | 29,970.93 |
| 버블 정렬 | 4,999,500,000 | 49,995,000.00 | 74,885,709.48 |
| 버블 정렬 (조기 종료) | 4,998,634,457 | 49,986,344.57 | 74,885,709.48 |
| 삽입 정렬 | 2,497,189,306 | 24,971,893.06 | 24,981,901.16 |

**선택 정렬과 버블 정렬의 비교 횟수는 정확히 n(n-1)/2 = 49,995,000회**이다. 두 알고리즘은 입력 값과 상관없이 정해진 범위를 항상 끝까지 훑기 때문이다. 선택 정렬은 최솟값을 찾으려고 남은 구간 전체를 매번 비교하고, 일반 버블 정렬은 순회마다 정해진 길이만큼 인접 비교를 한다.

**삽입 정렬의 비교 횟수는 약 24,971,893회로 위의 절반 정도**이다. 삽입 정렬은 이미 정렬된 앞부분에서 자기 자리를 찾는 순간 멈춘다. 무작위 데이터에서는 평균적으로 앞부분의 절반쯤만 되짚어 가면 자리를 찾는다.

**이동 횟수는 역전 쌍(inversion)의 개수로 설명된다.** 역전 쌍은 앞에 있는 값이 뒤에 있는 값보다 큰 쌍이다. 무작위 데이터의 기댓값은 n(n-1)/4 = 24,997,500쌍이고, 실험에서 구한 평균은 24,961,903쌍으로 거의 같다 (`버블 이동 ÷ 3`).
- 버블 정렬은 인접 교환으로 역전 쌍을 하나씩 없앤다. 교환 한 번이 이동 3회이므로 이동은 **역전 쌍 × 3 = 74,885,709**이다.
- 삽입 정렬은 역전 쌍 하나당 한 칸 밀기 1회이다. 여기에 원소마다 임시 저장 1회와 최종 삽입 1회가 붙어서 2(n-1) = 19,998회가 더해진다. 따라서 이동은 **역전 쌍 + 19,998 = 24,981,901**이다 (실측과 일치).
- 선택 정렬은 한 자리를 확정할 때 교환을 최대 1번만 한다. 교환은 많아야 9,999번이고, 이동 평균 29,970.93은 교환 약 9,990번 × 3과 같다. 원소가 이미 제자리에 있으면 교환을 생략하므로 9,999보다 조금 적다.

그래서 이동 횟수는 **선택(약 3만) ≪ 삽입(약 2,498만) < 버블(약 7,489만)** 순이다. 같은 역전 쌍을 해결하는 데 버블은 교환(3회), 삽입은 밀기(1회)를 쓰므로 버블이 삽입의 약 3배이다.

### 일반 버블 vs 조기 종료 버블

| | 평균 비교 횟수 | 이동 횟수 |
|---|---:|---:|
| 일반 버블 | 49,995,000.00 | 74,885,709.48 |
| 조기 종료 버블 | 49,986,344.57 | 74,885,709.48 |
| 차이 | **약 8,655회 (0.017%) 감소** | 동일 |

무작위 데이터에서는 조기 종료의 효과가 거의 없었다. 무작위 배열에서는 거의 마지막 순회 직전까지 교환이 계속 일어나기 때문이다. 줄어든 8,655회는 맨 끝의 아주 짧은 순회(약 130번)가 생략된 것에 해당한다. 이동 횟수가 똑같은 이유는 조기 종료가 **교환이 없는 순회를 건너뛸 뿐 교환 자체는 바꾸지 않기** 때문이다.

## 3. 입력 정렬 상태에 따른 비교 (n = 10,000)

정렬, 역순, 부분 정렬 데이터는 모두 **무작위 실험 1번째 시행의 데이터 하나**에서 만들어 같은 원본을 기준으로 비교했다.

### 3.1 이미 정렬된 데이터

원본을 key1 오름차순으로 `qsort` 해서 만들었다.

| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 0 |
| 버블 정렬 | 49,995,000 | 0 |
| 버블 정렬 (조기 종료) | **9,999** | 0 |
| 삽입 정렬 | **9,999** | 19,998 |

- 선택 정렬과 버블 정렬은 이미 정렬되어 있어도 비교가 49,995,000회로 줄지 않는다. 훑는 범위가 입력과 무관하게 고정이기 때문이다. 대신 교환이 필요 없으므로 이동은 0이다.
- **조기 종료 버블**은 첫 순회에서 교환이 한 번도 없으므로 그 순회(9,999회 비교)만 하고 종료한다. 일반 버블 대비 약 5,000배 감소로, 조기 종료가 가장 큰 효과를 내는 경우이다.
- **삽입 정렬**은 각 원소가 바로 앞 원소와 한 번만 비교하고 멈춰서 비교가 n-1 = 9,999회이다. 이동은 한 칸도 밀지 않지만, 임시 저장과 제자리 대입 때문에 2(n-1) = 19,998회가 발생한다. 이 이동은 정렬이 이미 되어 있어도 피할 수 없는 고정 비용이다.

### 3.2 역순으로 정렬된 데이터

위의 정렬 데이터를 거꾸로 뒤집어 만들었다.

| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 15,063 |
| 버블 정렬 | 49,995,000 | 149,984,868 |
| 버블 정렬 (조기 종료) | 49,995,000 | 149,984,868 |
| 삽입 정렬 | 49,995,000 | 50,014,954 |

- 모든 쌍이 역전이라 역전 쌍이 최대이다 (n(n-1)/2에서 key1이 같은 44쌍을 뺀 49,994,956쌍). 버블 이동 149,984,868 = 49,994,956 × 3이고, 삽입 이동 50,014,954 = 49,994,956 + 19,998이다.
- 삽입 정렬은 매번 앞부분 전체를 끝까지 밀어야 해서 비교가 최댓값 n(n-1)/2까지 늘어난다. **삽입 정렬의 최악 입력**이다.
- 조기 종료 버블은 **매 순회에 교환이 발생하므로 종료 조건이 한 번도 작동하지 않아** 일반 버블과 결과가 완전히 같다.
- 선택 정렬의 이동은 15,063회(교환 약 5,021번)로 오히려 적다. 첫 원소와 마지막 원소를 바꾸는 식으로 바깥쪽부터 교환하다 보면, 약 n/2번 교환한 시점에 가운데 부분은 이미 제자리에 와 있어 나머지는 교환이 필요 없기 때문이다.

### 3.3 일부 정렬된 데이터

**생성 방법.** 정렬된 데이터에서 **서로 다른 두 위치를 무작위로 골라 교환하는 작업을 N/20 = 500번(전체의 약 5%)** 수행했다. 대부분의 원소는 제자리에 있고, 일부만 흐트러진 거의 정렬된 상태이다. 교란 횟수를 고정해 두었기 때문에 "얼마나 정렬되어 있는지"를 명확히 설명할 수 있고, 시드를 고정해 항상 같은 데이터가 만들어진다.

**인공지능 활용.** 부분 정렬 데이터를 만드는 방법을 조사하는 데 AI(Claude)를 활용했다. "정렬된 데이터에 일부 원소의 위치를 무작위로 교환", "일정 구간만 섞기", "소수의 무작위 교란" 같은 후보를 비교했고, 교란 정도를 교환 횟수 하나로 조절할 수 있어서 설명하기 쉬운 첫 번째 방법을 골랐다. 코드 구조 설계와 결과 분석 초안 작성에도 AI의 도움을 받았고, 수치는 모두 직접 실행해서 확인했다.

| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 1,506 |
| 버블 정렬 | 49,995,000 | 8,658,021 |
| 버블 정렬 (조기 종료) | 49,715,622 | 8,658,021 |
| 삽입 정렬 | 2,896,004 | 2,906,005 |

- **교환 500번만 했는데 역전 쌍은 약 288만 개**(8,658,021 ÷ 3 = 2,886,007)이다. 위치를 서로 바꾼 두 원소가 멀리 떨어져 있으면, 그 사이에 있는 원소 하나하나와 새로 역전 쌍을 만들기 때문이다 (무작위로 고른 두 위치의 평균 거리는 약 n/3). 그래서 "5%만 흐트러뜨렸다"가 곧 "역전 쌍 5%"는 아니다. 그래도 무작위(약 2,496만)의 약 11.6%밖에 안 된다.
- **삽입 정렬**은 비교와 이동이 역전 쌍에 비례해서 무작위의 약 1/9 수준(약 290만)으로 줄었다. 정렬 상태에 가장 잘 적응하는 알고리즘이다.
- **선택 정렬**은 비교가 그대로 49,995,000회이고, 이동은 1,506회(교환 약 502번)로 교란 횟수에 맞춰 줄었다. 비교는 입력을 가리지 않고 이동만 줄어드는 알고리즘이다.
- **조기 종료 버블**은 비교가 49,995,000 → 49,715,622로 **약 0.56%밖에 줄지 않았다.** 줄어든 279,378회는 마지막 747번의 순회가 생략된 것이다 (1+2+…+747 = 279,378). 총 9,252번의 순회를 수행한 셈이다. 이유는 버블 정렬이 **작은 값을 한 순회에 한 칸씩만 앞으로 보내기** 때문이다. 교란으로 작은 값이 뒤쪽에 놓이면 그 값이 앞으로 오기까지 거의 n번에 가까운 순회가 필요하고, 그동안은 교환이 계속 일어나서 종료 조건이 작동하지 않는다. 즉 **조기 종료는 "완전히 정렬됐을 때"만 크게 효과가 있고, "거의 정렬됐을 때"는 효과가 작다.**

## 4. 안정성 검증

### 방법
각 데이터에 원래 입력 순번 `order`를 저장하고, 정렬 후 **key1이 같은 인접한 데이터 쌍에서 `order`가 큰 쪽이 앞에 있으면 위반 1회**로 센다. 안정 정렬이라면 key1이 같은 데이터는 원래 순서대로 나열되므로 위반이 0이어야 한다. 위반이 하나라도 있으면 불안정이다.

### 검증에 사용한 입력 데이터
무작위 10,000개에서는 key1이 겹치는 경우가 많지 않을 수 있어서 3종류로 검증했다.

1. **과제 예시 4개**: `(527,100) (527,200) (125,300) (892,400)`
2. **중복이 많은 1,000개**: key1을 0~99로 제한한 데이터. 정렬 후 key1이 같은 인접 쌍이 900개이다.
3. **무작위 10,000개** (1번째 시행 데이터): key1이 같은 인접 쌍이 44개이다.

### 결과

| 알고리즘 | 예시 4개 정렬 결과 | 1,000개 위반 | 10,000개 위반 | 판정 |
|---|---|---:|---:|---|
| 선택 정렬 | (125,300) (527,**200**) (527,**100**) (892,400) | 302 | 20 | **불안정** |
| 버블 정렬 | (125,300) (527,100) (527,200) (892,400) | 0 | 0 | **안정** |
| 삽입 정렬 `>` | (125,300) (527,100) (527,200) (892,400) | 0 | 0 | **안정** |
| 삽입 정렬 `>=` | (125,300) (527,**200**) (527,**100**) (892,400) | 900 | 44 | **불안정** |

### 결과가 나온 원인
- **선택 정렬(불안정):** 최솟값을 찾아 현재 위치와 **멀리 떨어진 위치끼리 교환**한다. 예시 데이터에서 index 0에 `(125,300)`을 가져오려고 index 0의 `(527,100)`과 교환하면, `(527,100)`이 index 2로 날아가 `(527,200)` 뒤에 놓인다. 같은 키 사이를 건너뛰는 교환이 생기기 때문에 순서가 바뀐다.
- **버블 정렬(안정):** **인접한** 두 원소만 교환하고, 조건이 `>`(엄격한 크다)라서 키가 같으면 교환하지 않는다. 같은 키를 가진 원소끼리는 서로를 추월할 수 없으므로 순서가 유지된다.
- **삽입 정렬(`>`와 `>=`):** 아래에서 따로 설명한다.

### 삽입 정렬에서 `>`와 `>=`의 차이
삽입 정렬은 `current`를 넣을 자리를 찾으려고 뒤에서부터 `data[j]`와 비교하며 한 칸씩 민다.

- **Case A `data[j].key1 > current.key1`**: 키가 **같으면 밀지 않고 멈춘다.** `current`는 같은 키의 원소들 **뒤**에 들어가므로 원래 순서가 유지된다 → 안정.
- **Case B `data[j].key1 >= current.key1`**: 키가 **같아도 밀어 버린다.** `current`는 같은 키의 원소들 **앞**에 들어가므로 같은 키끼리 순서가 뒤집힌다 → 불안정.

실험에서도 차이가 분명했다. 예시 4개에서 `>`는 `(527,100) (527,200)`을 유지했지만 `>=`는 `(527,200) (527,100)`으로 뒤집었다. 중복이 많은 1,000개에서는 `>=`가 인접한 같은 키 쌍 900개를 **전부** 뒤집었고(위반 900), `>`는 0이었다. 10,000개에서도 `>=`는 44쌍 모두 뒤집혔다.

성능도 조금 달라졌다. 1,000개 데이터에서 `>=`는 같은 키를 불필요하게 한 번씩 더 밀기 때문에 비교가 247,318 → 252,289회, 이동이 248,319 → 253,299회로 늘었다. 즉 `>=`는 **안정성을 잃으면서 일도 더 하는** 선택이다.

연산자 선택이 안정성을 바꾼다는 점은 버블 정렬에도 같다. 버블 정렬의 교환 조건을 `>=`로 바꾸면 같은 키끼리도 교환해서 불안정해질 것이다 (이 실험에서 직접 측정하지는 않았다).

## 5. 종합 분석

### 입력 상태가 알고리즘에 미치는 영향

| 알고리즘 | 비교 횟수 | 이동 횟수 |
|---|---|---|
| 선택 정렬 | 입력과 무관하게 **항상 49,995,000** | 교환이 필요한 만큼만 발생 (0 ~ 약 3만). 가장 적음 |
| 버블 정렬 | 입력과 무관하게 항상 49,995,000 | **역전 쌍 × 3.** 정렬 0 → 부분 약 866만 → 무작위 약 7,489만 → 역순 약 1.5억 |
| 조기 종료 버블 | 정렬 상태 9,999회, 부분 정렬 거의 불변(0.56% 감소), 무작위·역순은 변화 없음 | 일반 버블과 동일 |
| 삽입 정렬 | **역전 쌍에 비례.** 정렬 9,999 → 부분 약 290만 → 무작위 약 2,497만 → 역순 49,995,000 | 역전 쌍 + 2(n-1) |

데이터가 이미 정렬되어 있을수록 **적응형 알고리즘(삽입 정렬, 조기 종료 버블)** 은 비교와 이동이 크게 줄지만, **선택 정렬은 비교가 전혀 줄지 않는다.** 이동 횟수는 모든 알고리즘에서 정렬에 가까울수록 줄어든다.

### 알고리즘 간 성능 차이의 원인
1. **"역전 쌍을 얼마나 직접 이용하는가"가 핵심이다.** 삽입 정렬은 자리를 찾으면 멈추기 때문에 일의 양이 역전 쌍 개수에 비례한다. 선택 정렬은 최솟값 탐색 때문에 항상 전체를 훑는다. 버블 정렬은 비교 범위가 고정이고 교환 비용(3회)까지 커서 이동이 가장 많다.
2. **이동 비용:** 선택 정렬은 원소당 교환 최대 1번이라 이동이 가장 적다. 데이터가 커서 복사 비용이 큰 상황이라면 선택 정렬이 유리할 수 있다. 하지만 불안정하다.
3. **조기 종료는 만능이 아니다:** 정렬이 "완전히" 끝난 입력에서만 극적인 효과가 있다. 일부만 흐트러져도 작은 값이 한 칸씩만 이동하는 버블 정렬의 특성 때문에 대부분의 순회를 그대로 수행한다.
4. **안정성은 구현 방식(교환 위치, 비교 연산자)에서 나온다:** 멀리 떨어진 원소를 교환하는 선택 정렬은 불안정하고, 인접 교환 또는 엄격한 부등호(`>`)로 같은 키를 추월하지 않는 버블 정렬과 삽입 정렬 `>`는 안정하다.

### 결론
이번 실험 조건에서는 **삽입 정렬(`>`)이 비교 횟수, 이동 횟수, 안정성을 모두 고려했을 때 가장 균형이 좋았고**, 특히 거의 정렬된 데이터에서 성능이 크게 좋아졌다. 버블 정렬은 안정하지만 이동이 가장 많고, 조기 종료의 이득은 완전히 정렬된 입력에 한정된다. 선택 정렬은 이동이 가장 적은 대신 입력과 무관하게 비교가 일정하고 불안정하다.
