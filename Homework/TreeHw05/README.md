# 과제 05: 순차 탐색과 이진 탐색 트리 탐색의 비교

## 1. 파일 구성

| 파일 | 내용 |
|---|---|
| `BST.h` | Node 구조체, BST 및 탐색 함수 선언 |
| `BST.c` | BST 생성/삽입/탐색, 순차 탐색, 메모리 해제 구현 |
| `main.c` | 데이터 생성, 탐색 실행, 결과 출력 |

## 2. 구현 방식

- 0~1,000 범위에서 서로 다른 정수 100개를 생성합니다. 이미 나온 값이면 다시 생성합니다.
- 100개를 발생 순서 그대로 배열에 저장하고(정렬하지 않음), 같은 순서로 BST에 삽입합니다.
- BST는 `data`, `left`, `right`를 가진 노드를 포인터로 연결한 구조입니다.
- 탐색 키 50개를 추가로 생성하고, 각 키마다 순차 탐색과 BST 탐색을 모두 수행합니다.
- 비교 횟수 기준
  - 순차 탐색: 배열 원소와 키를 비교할 때마다 1회
  - BST 탐색: 방문한 노드의 값과 키를 비교할 때마다 1회
  - BST 생성: 삽입 위치를 찾으며 기존 노드와 비교할 때마다 1회

## 4. 분석

### 4-1. 두 탐색 방법의 성능 차이

실행 결과 BST 탐색의 평균 비교 횟수는 10.30회, 순차 탐색은 93.04회로 약 9배 차이가 났습니다.

이런 차이가 생기는 이유는 두 방법이 탐색 범위를 줄이는 방식이 다르기 때문입니다.

- **순차 탐색**은 배열이 정렬되어 있지 않아 키의 위치를 알 수 없으므로 앞에서부터 하나씩 확인해야 합니다. 비교 한 번에 후보가 하나씩만 줄어들어 최악의 경우 n번(여기서는 100번)까지 비교합니다. 키가 없는 경우에는 항상 배열 전체를 확인해야 실패를 알 수 있습니다.
- **BST 탐색**은 노드와 비교할 때마다 키가 더 작은지 큰지에 따라 한쪽 서브트리 전체를 버립니다. 그래서 비교 횟수가 루트에서 내려간 깊이, 즉 트리의 높이에 비례합니다.
<img width="360" height="1016" alt="image" src="https://github.com/user-attachments/assets/b25ba19a-17c2-4182-9f04-2e5941f83d00" />
- **위 사진과 같이** 순차 탐색은 실패하였다는 것을 알기 위해 배열을 끝까지 다 돌아야하지만, BST탐색은 실패여부를 순차탐색보다 압도적으로 빠르게 알아낸다는 것을 알수있음
- **추가로** 성공 여부의 경우 순차탐색은 비교 횟수가 들쑥날쑥하지만 BST탐색의 경우 기복없이 일정하게 빠른 속도로 알아낸다는 것을 알 수 있음.


### 4-2. BST 생성 비용을 고려했을 때의 성능 차이

배열은 값을 순서대로 저장하면 되므로 생성에 비교가 필요 없습니다. 반면 BST는 값을 삽입할 때마다 위치를 찾기 위해 기존 노드와 비교해야 하며, 이번 실행에서 100개를 삽입하는 데 753회의 비교가 발생했습니다.

따라서 BST의 총 비용은 생성 비교 753회 + 탐색 비교 515회 = 1268회이고, 순차 탐색의 총 비교 4652회와 비교하면 BST탐색이 비용적인 부분에서 이점이 있었습니다.

손익분기점은 다음과 같이 계산할 수 있습니다.

- 탐색 1회당 BST가 줄여주는 비교 횟수 = 순차 평균 − BST 평균 = 82.74
- 생성 비용을 회수하는 데 필요한 탐색 횟수 = BST 생성 비교 횟수 ÷ 위 값 = 9.1회

즉 같은 데이터를 약 10회 이상 탐색하면 BST가 이득입니다. 한두 번만 탐색하고 끝난다면 트리를 만드는 비용 때문에 순차 탐색이 더 나을 수 있고, BST는 한 번 만들어 두고 여러 번 탐색할 때 의미가 있습니다. 이 분석은 숫자 비교 횟수만 기준으로 했으며 노드 동적 할당 비용 등은 포함하지 않았습니다.

따라서 50회 탐색에 있어서는 BST탐색이 더 유리했습니다.


### 4-3. 트리 구조에 따른 탐색 성능 변화

BST의 탐색 비용은 트리의 **높이**에 의해 결정되고, 높이는 데이터를 **삽입하는 순서**에 따라 달라집니다.

- **균형 잡힌 트리**: 노드가 100개이면 높이가 약 7로 가장 낮고, 탐색 비교 횟수는 log₂n 수준입니다.
- **무작위 순서로 삽입한 트리(이번 실험)**: 작은 값과 큰 값이 섞여 들어와 트리가 어느 정도 양쪽으로 퍼집니다. 다만 완전히 균형이 잡히지는 않아 가지마다 깊이가 다릅니다.
- **한쪽으로 치우친 트리(최악의 경우)**: 오름차순이나 내림차순처럼 이미 정렬된 순서로 삽입하면 모든 노드가 한쪽 자식으로만 이어져 연결 리스트 모양이 됩니다. 높이가 n(=100)이 되어 탐색 한 번에 최대 100회를 비교하게 되고, 이는 순차 탐색과 같은 O(n)입니다. 생성 비용도 n(n−1)/2 = 4,950회까지 커져 BST의 이점이 사라집니다.


이처럼 BST가 빠른 것은 자료구조 자체 때문이 아니라 트리가 균형을 유지한다는 전제 때문입니다. 입력 순서에 상관없이 성능을 보장하려면 AVL 트리나 레드-블랙 트리처럼 삽입할 때 스스로 균형을 맞추는 트리가 필요합니다.

## 5. 결론

- 같은 데이터에서 BST 탐색은 순차 탐색보다 비교 횟수가 약 9배 적었습니다.
- BST 생성 비용(753회)을 포함해도 총 비교 횟수는 1268회로 순차 탐색(4652회)보다 약 3.7배 적었습니다.
- 다만 이 이점은 같은 데이터를 여러 번 탐색하고, 트리가 한쪽으로 심하게 치우치지 않았을 때 성립합니다.
- 난수를 사용하므로 실행할 때마다 BST 생성 비교 횟수, BST 탐색 평균, 손익분기점(이번 실행 기준 약 9.1회) 같은 수치는 조금씩 달라질 수 있습니다. 그러나 순차 탐색은 키가 없을 때 항상 배열 전체(100회)를 확인하고, BST는 트리의 높이만큼만 내려가므로 두 방법의 격차(이번 실행 약 9배)는 실행마다 크게 바뀌지 않습니다.
- 이번 실험의 탐색 횟수(50회)는 손익분기점(약 9~10회)보다 훨씬 많아서, BST 생성 비용을 포함해도 총 비교 횟수가 순차 탐색보다 적었습니다. 따라서 이 조건(무작위 100개 삽입, 50회 탐색)에서는 실행 결과가 조금 달라져도 BST 탐색이 더 유리하다는 결론은 유지됩니다.
