# 과제 07: 인접 행렬과 인접 리스트의 성능 비교

## 1. 개요

정점 100개인 무방향 단순 그래프를 **희소 그래프(간선 100개)** 와 **밀집 그래프(간선 4,000개)** 로 랜덤 생성하고,
각각을 **인접 행렬**과 **인접 리스트**로 표현하여 메모리 사용량과 연산별 비교 횟수를 측정했다.
두 표현 방식은 같은 간선 목록으로 만든 동일한 그래프이며, 연산에 쓰는 정점 쌍도 똑같이 적용했다.

| | 정점 수 | 간선 수 | 
|---|---|---|
| 희소 그래프 | 100 | 100 |
| 밀집 그래프 | 100 | 4,000 |

## 2. 파일 구성

| 파일 | 내용 |
|---|---|
| `graph.h` | 상수, 구조체(`graphNode`, `matrixGraph`, `listGraph`), 함수 선언 |
| `graph.c` | 랜덤 간선 생성, 인접 행렬 / 인접 리스트의 생성·삽입·삭제·조회 함수 구현 |
| `main.c` | 희소/밀집 그래프 생성, 테스트 대상 선택, 4가지 케이스 측정 및 출력 |


## 3. 측정 방법

### 3-1. 메모리 용량 (Byte)
<img width="1356" height="1086" alt="image" src="https://github.com/user-attachments/assets/bbd25fee-4e73-4198-bc22-8c8f6ee44c60" />

`sizeof`로 계산했다. 난수 생성에 쓴 임시 배열과 `malloc` 내부 관리 영역은 제외했다.

- **인접 행렬**: `sizeof(matrixGraph)` = 정점 수 `n`(4B) + 100 × 100 × 4B = **40,004B**. 간선 수와 상관없이 항상 같다.
- **인접 리스트**: `sizeof(listGraph)` + 노드 수 × `sizeof(graphNode)`
  - `listGraph` = `n`(4B) + 패딩(4B) + 헤드 포인터 100개 × 8B = 808B
  - `graphNode` = `vertex`(4B) + 패딩(4B) + `link` 포인터(8B) = 16B
  - 무방향 그래프라 간선 1개당 노드가 2개 필요하므로 노드 수 = 간선 수 × 2

### 3-2. 비교 횟수의 기준

행렬의 칸 또는 리스트의 노드를 **한 번 확인할 때마다 비교 1회**로 센다. 전역 변수 `compareCount`를 연산 직전에 0으로 만들고 연산 후에 읽었다.

| 연산 | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 간선 삽입 | 이미 있는지 `adjMatrix[u][v]` 확인 → 1회 | 이미 있는지 u의 리스트를 끝까지 확인 → **u의 차수**만큼 |
| 간선 삭제 | 존재 확인 `adjMatrix[u][v]` → 1회 | u의 리스트에서 v를 찾을 때까지 + v의 리스트에서 u를 찾을 때까지 확인한 노드 수의 합 |
| 연결 여부 확인 | `adjMatrix[u][v]` → 1회 | u의 리스트에서 v를 찾을 때까지 확인한 노드 수 (없으면 끝까지) |
| 인접 정점 출력 | u행 100칸 전부 확인 → 100회 | u의 리스트 노드 전부 확인 → u의 차수 |

- 값을 바꾸는 동작(행렬 칸에 0/1 대입, 리스트 맨 앞에 노드 추가, 포인터 연결)은 "확인"이 아니므로 비교에 넣지 않았다.
- 리스트 삽입은 u의 리스트가 비어 있으면(차수 0) 확인할 노드가 없어서 비교 횟수가 0이 될 수 있다.

### 3-3. 연산 대상 선택

| 연산 | 대상 선택 방법 |
|---|---|
| 삽입 | 서로 다르고, 현재 그래프에 **없는** 정점 쌍 |
| 삭제 | 생성한 간선 목록에서 하나를 뽑아 **반드시 존재하는** 간선 |
| 연결 확인 | 서로 다른 임의의 두 정점 (연결 여부는 무관) |
| 인접 정점 출력 | 임의의 정점 하나 |

실행할 때마다 랜덤 그래프와 정점 쌍이 새로 만들어지므로 숫자는 매번 조금씩 달라진다.

## 5. 분석

### 5-1. 메모리 사용량

- 인접 행렬은 정점 수만 정해지면 크기가 고정이라 두 그래프에서 모두 **40,004B**로 같았다. 간선이 100개든 4,000개든 100 × 100칸을 항상 잡아 둔다.
- 인접 리스트는 간선 수에 비례해 늘어난다. 노드 수가 희소 그래프는 200개(= 100 × 2), 밀집 그래프는 8,000개(= 4,000 × 2)이고, 노드 하나가 16B라서 각각 3,200B와 128,000B에 구조체 808B가 더해져 **4,008B**와 **128,808B**가 나왔다.
- 희소 그래프에서는 리스트가 행렬의 약 1/10이고, 밀집 그래프에서는 리스트가 행렬의 약 3.2배였다.
- 리스트는 노드마다 포인터(8B)를 따로 가지므로 간선 하나를 저장하는 비용이 행렬(칸 하나 4B)보다 크다. 계산상 `808 + 32 × 간선 수 > 40,004`가 되는 간선 약 1,225개(전체 가능한 간선 4,950개의 약 25%)부터 리스트가 행렬보다 메모리를 더 쓴다.

### 5-2. 간선 삽입 및 삭제의 비교 횟수

- **인접 행렬**은 `adjMatrix[u][v]` 위치를 바로 알 수 있어서 삽입과 삭제 모두 **1회**였고, 그래프 밀도와 상관이 없었다.
- **인접 리스트**는 위치를 찾으려면 리스트를 따라가야 해서 정점의 차수에 따라 비교 횟수가 달라졌다.
  - 삽입은 u의 리스트를 끝까지 확인하므로 u의 차수만큼 비교한다. 희소 그래프에서는 2회, 밀집 그래프에서는 u의 차수가 80이라 **80회**였다.
  - 삭제는 u의 리스트와 v의 리스트를 각각 탐색하므로 양쪽에서 확인한 노드 수를 합친다. 희소 그래프에서는 3회, 밀집 그래프에서는 **128회**였다.
- 같은 리스트 연산이라도 희소 그래프에서는 2~3회로 행렬과 거의 차이가 없었고, 밀집 그래프에서는 80~128배까지 차이가 벌어졌다. 그래프가 밀집할수록 정점당 리스트가 길어지기 때문이다.

### 5-3. 두 정점의 연결 여부 확인

- 행렬은 칸 하나만 보면 되어서 두 그래프 모두 **1회**였다.
- 리스트는 u의 리스트에서 v를 찾을 때까지 확인한다. v를 찾으면 바로 멈추고, 연결되어 있지 않으면 리스트 전체(= u의 차수)를 확인해야 한다.
  - 희소 그래프의 (91, 94)는 연결되어 있지 않아서 91번의 리스트를 끝까지 확인한 **3회**였다.
  - 밀집 그래프의 (84, 27)은 연결되어 있고 리스트의 9번째 노드에서 찾아서 **9회**였다.
- 밀집 그래프의 9회는 v가 리스트 앞쪽에 있었던 경우이고, 뒤쪽에 있거나 연결되어 있지 않다면 최대 약 80회까지 늘어날 수 있다. 연결 여부 확인은 v의 위치에 따라 1회부터 차수까지 달라지는 연산이다.

### 5-4. 특정 정점의 인접 정점 출력

- 행렬은 해당 정점의 행 100칸을 전부 확인해야 인접 정점을 알 수 있어서, 인접 정점이 몇 개든 항상 **100회**였다.
- 리스트는 노드가 곧 인접 정점이라 **인접 정점 수만큼만** 확인한다.
  - 희소 그래프: 3개의 인접 정점을 3회로 출력 (행렬 대비 약 1/33)
  - 밀집 그래프: 77개의 인접 정점을 77회로 출력 (행렬 대비 약 3/4)
- 그래프가 밀집해질수록 인접 정점이 100개에 가까워져서 리스트의 이점이 줄어든다.

### 5-5. 희소 그래프에서의 차이

희소 그래프는 가능한 간선 4,950개 중 2%만 존재하고 정점당 연결이 평균 2개뿐이다.
행렬은 10,000칸 중 값이 1인 칸이 200개뿐이어서 대부분이 낭비된다. 리스트는 있는 간선만 노드로 저장해서 메모리가 **약 1/10(4,008B vs 40,004B)** 이었고, 인접 정점 출력도 **3회 vs 100회**로 훨씬 적었다.
반면 리스트의 삽입·삭제·연결 확인은 정점당 연결이 몇 개 안 되어서 2~3회에 그쳤고, 행렬의 1회와 큰 차이가 나지 않았다.
따라서 희소 그래프에서는 리스트가 메모리와 인접 정점 탐색에서 크게 이득이고 나머지 연산에서는 손해가 거의 없다.

### 5-6. 밀집 그래프에서의 차이

밀집 그래프는 가능한 간선의 약 81%가 존재해서 행렬의 칸이 대부분 의미 있는 값(1)으로 채워진다. 행렬은 메모리를 낭비하지 않으면서 삽입·삭제·연결 확인이 모두 **1회**로 끝난다.
리스트는 간선이 많아 노드 8,000개와 포인터 때문에 메모리가 **128,808B로 행렬의 약 3.2배**였고, 정점당 리스트가 길어져서 삽입 80회, 삭제 128회처럼 비교가 크게 늘었다. 인접 정점 출력도 77회 vs 100회로 거의 이득이 없었다.
따라서 밀집 그래프에서는 행렬이 메모리와 대부분의 연산에서 유리하다.

### 5-7. 어떤 경우에 무엇을 사용하는 것이 적절한가

| 상황 | 적절한 표현 | 이유 |
|---|---|---|
| 간선이 적은 희소 그래프 | 인접 리스트 | 있는 간선만 저장해서 메모리가 적고, 인접 정점을 차수만큼만 확인 |
| 정점의 인접 정점을 자주 순회 (예: DFS, BFS) | 인접 리스트 | 인접 정점 출력이 차수에 비례 (행렬은 항상 정점 수만큼) |
| 간선이 많은 밀집 그래프 | 인접 행렬 | 메모리 낭비가 적고 포인터 오버헤드가 없음 |
| 두 정점의 연결 여부 확인, 간선 삽입·삭제가 잦음 | 인접 행렬 | 칸 하나로 바로 접근해서 항상 1회 |
| 정점 수가 크지만 간선이 적음 | 인접 리스트 | 행렬은 정점 수의 제곱만큼 메모리가 필요 |

## 6. 결론

인접 행렬은 간선 수와 상관없이 메모리가 고정이고 간선 단위 연산(삽입·삭제·연결 확인)이 항상 1회로 빠르지만, 인접 정점을 찾을 때는 항상 정점 수만큼 확인해야 한다.
인접 리스트는 메모리와 비교 횟수가 간선 수(차수)에 비례해서, 희소 그래프에서는 매우 효율적이지만 밀집해질수록 행렬보다 메모리도 더 쓰고 연산도 느려진다.
따라서 그래프의 밀도와 주로 사용하는 연산이 무엇인지에 따라 표현 방식을 선택해야 한다.
