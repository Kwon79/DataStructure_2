# 과제 12: 퀵 정렬의 피벗 선택에 따른 성능 비교

## 1. 실험 방법

- 같은 크기에서는 하나의 원본 데이터를 복사해서 세 방법에 똑같이 사용
- 세 방법은 **피벗 선택 부분만 다르고** 분할(partition) 알고리즘은 동일
- 비교 횟수: 분할 중 데이터와 피벗의 비교 + Median-of-Three의 중앙값 결정 비교만 카운트 (인덱스/종료 조건 검사, 난수 생성, 데이터 이동은 제외)
- 매 정렬 후 오름차순 여부를 검증
- 무작위 데이터와 무작위 피벗 때문에 실행마다 값이 달라지므로, 프로그램을 **5회 실행해서 평균**을 분석에 사용 (5회 실행 화면은 첨부 이미지 참고)

## 3. 비교·분석

### 3.1 데이터 크기 증가에 따른 변화

세 방법 모두 n이 2배가 될 때 비교 횟수가 약 2.1배씩 늘었다(예: First는 2.25 → 2.22 → 2.17 → 2.18배). 정확히 2배가 아니라 조금 더 큰 것은 비교 횟수가 n에 log n이 곱해진 O(n log n) 꼴로 증가하기 때문이다. 16,000개에서 20,000개로 n이 1.25배 늘었을 때도 비교 횟수는 약 1.26~1.29배로, 선형보다 조금 더 가파르게 늘어 같은 패턴을 보였다. First의 경우 n·log₂n 대비 비교 횟수가 n=1,000에서 약 1.15배, n=20,000에서 약 1.20배였다. n이 커질수록 방법 간 비교 횟수의 절대 차이도 커졌다.

### 3.2 피벗 선택 방법별 성능 차이

- **Median-of-Three**: 평균 기준으로 First보다 모든 크기에서 적었고(약 2 ~~ 7%), n이 클수록 차이가 커지는 경향이 있었다. 8,000개 이상에서는 5번의 실행 중 대부분(8,000개와 20,000개는 5번 모두)에서 세 방법 중 가장 적었다. Random과 비교하면 2,000개, 8,000개, 16,000개, 20,000개에서는 적었지만, 1,000개(11,263 vs 11,259)와 4,000개(54,876 vs 54,611)에서는 거의 같거나 Random이 약간 적었다.
First vs Random: 6개 크기 중 5개(1,000~~16,000개)에서 Random이 First보다 적었고(-0.9% *~* -4.5%), 20,000개에서만 First가 약간 적었다(+1.0%). 따라서 이 실험에서는 Random이 First보다 근소하게 더 나았다. 다만 차이는 크지 않았다.

### 3.3 왜 이런 차이가 생기는가

퀵 정렬의 비교 횟수는 분할 결과가 얼마나 **균형 있게 나뉘느냐**로 결정된다. 피벗이 구간의 중앙값에 가까울수록 좌우가 비슷하게 나뉘어 재귀 깊이가 log n에 가까워지고, 한쪽으로 치우칠수록 깊이가 늘어나 비교가 많아진다. 각 분할에서는 구간 크기만큼 비교가 일어나므로, 깊이가 얕을수록 총 비교가 적다.

- **First와 Random이 비슷한 이유**: 데이터 자체가 무작위이므로 구간의 첫 번째 원소도 이미 "무작위 위치에 있는 값"과 통계적으로 같다. 그래서 피벗을 따로 무작위로 뽑아도 평균적인 분할 균형은 같고, 관측된 차이는 우연(노이즈)에 가깝다. 실제로 Random은 같은 크기에서도 실행마다 값이 크게 흔들렸다(예: 16,000개에서 256,265 ~ 279,168).
- **Median-of-Three가 더 적은 이유**: 세 값의 중앙값은 하나를 뽑을 때보다 구간의 중앙값에 가까울 확률이 높아서 분할이 더 균형 있게 된다. 이론적으로 평균 비교 횟수의 최고차항은 First/Random이 약 1.39·n·log₂n, Median-of-Three가 약 1.19·n·log₂n으로 약 14% 차이가 난다. 실측 차이(최대 약 7%)가 이보다 작은 것은, 분할마다 중앙값을 정하느라 비교가 몇 번씩 추가로 들어가고(작은 구간이 많을수록 이 비중이 커진다), 저차항의 영향도 있기 때문이다. n=1,000처럼 작은 크기에서 차이가 작은 것도 같은 이유다.

### 3.4 어떤 방법이 효과적이었는가

이 실험(무작위 데이터)에서는 **Median-of-Three가 가장 효과적**이었다. 다만 이 결론에는 한계가 있다.

- 5회 평균이라 표본이 적고, 작은 크기(1,000개, 4,000개)에서는 Random과 거의 같았다.
- 이번 데이터는 무작위라 First도 나쁘지 않게 나왔다. (아래는 이번에 측정하지 않은 이론적 설명이다.) 이미 정렬되었거나 역순인 데이터에서는 First의 피벗이 항상 최솟값/최댓값이 되어 분할이 한쪽으로만 치우치고, 비교 횟수가 O(n²)까지 늘어난다. Random은 입력 순서와 무관하게 이런 최악이 나올 확률이 매우 낮아 안정적이고, Median-of-Three는 정렬된 데이터에서 가운데 값이 뽑혀 균형 있게 나뉜다.
- 따라서 입력 분포를 모를 때는 Random이나 Median-of-Three가 안전하고, 이번 무작위 데이터에서는 그중 Median-of-Three가 비교 횟수가 가장 적었다.

## 4. [보너스] 재귀적 vs 반복적 퀵 정렬

두 구현은 같은 데이터(n = 10,000), 같은 피벗(Median-of-Three), 같은 `partition`을 사용했다. 정렬 호출 구간만 측정했고(데이터 생성, 배열 복사, 검증, 출력 제외) 한 번 실행할 때 200회 반복해 평균을 냈으며, 프로그램을 5회 실행한 결과는 다음과 같다.

| 실행 | Recursive (ms) | Iterative (ms) |
|---:|---:|---:|
| 1 | 1.0030 | 1.0320 |
| 2 | 0.9883 | 1.0040 |
| 3 | 1.0031 | 1.0252 |
| 4 | 1.0469 | 1.0768 |
| 5 | 0.9995 | 1.0384 |
| 평균 | 1.0082 | 1.0353 |

### 분석

재귀적 퀵 정렬이 반복적 퀵 정렬보다 **근소하게 빨랐다**(평균 1.008 ms vs 1.035 ms, 약 2.7% 차이, 5회 모두 같은 경향).

- **원인**: 두 방식은 같은 분할 알고리즘을 쓰므로 비교 횟수와 데이터 이동은 같고, 차이는 정렬할 구간을 관리하는 방식에서 나온다. 반복적 방식은 구간의 시작과 끝을 직접 만든 스택에 저장하고 꺼내는 코드(분할마다 push/pop, 시작 시 메모리 할당/해제)를 추가로 실행해야 하는 반면, 재귀적 방식은 함수 호출 스택으로 이를 처리한다. 이 추가 작업이 반복적 방식의 실행시간을 약간 늘린 것으로 분석된다. 
- **정리**: 차이가 작으므로 반복적 퀵 정렬이 항상 느린 것은 아니며, 실제 성능은 구현 방식과 실행 환경(최적화 여부 등)에 따라 달라질 수 있다.

## 5. 결론

1. 세 방법 모두 비교 횟수는 O(n log n) 패턴으로 증가했다.
2. 무작위 데이터에서 Median-of-Three가 평균적으로 가장 적게 비교했고(First 대비 약 2~7%), First와 Random은 구분하기 어려울 정도로 비슷했다.
3. 차이의 원인은 피벗이 만드는 분할의 균형이며, 이는 입력 데이터의 정렬 상태에 따라 더 크게 벌어질 수 있다.
4. 재귀/반복 퀵 정렬은 같은 알고리즘이므로 실행시간이 거의 같았고, 차이는 호출/스택 관리 방식의 오버헤드 정도였다.
