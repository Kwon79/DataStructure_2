# 삽입 정렬 vs 쉘 정렬 비교 횟수 분석

동일한 무작위 데이터에 대해 **삽입 정렬**, **쉘 정렬(기본 간격)**, **쉘 정렬(Knuth 간격)** 을 수행하고, 데이터 값 사이의 비교 횟수를 측정해 성능 차이의 원인을 분석한다.

## 1. 실험 방법

| 파일 | 설명 |
|---|---|
| `sort.h` | 헤더 파일: 정렬 함수, 정렬 검증, 난수 생성 함수 선언 |
| `sort.c` | 구현 파일: 삽입 정렬, 쉘 정렬(기본/Knuth), 비교 횟수 측정, 정렬 검증, 난수 생성 |
| `main.c` | 실행 파일: 데이터 생성, 정렬 수행, 검증, 결과 출력 |

- 데이터 크기 n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000. 크기마다 무작위 정수 원본 배열을 한 번 만들고, 세 정렬 모두 그 원본의 복사본(`memcpy`)으로 수행한다. 데이터 생성과 복사는 비교 횟수에 포함하지 않는다.
- 난수는 시드를 고정한 xorshift32로 직접 생성한다. `rand()`는 컴파일러마다 범위(MSVC 0~32767, gcc 0~2^31-1)가 달라 결과가 달라지므로, 어떤 환경에서도 같은 데이터와 같은 비교 횟수가 나오게 했다.
- 비교 횟수는 `a[j - gap] > key` 같은 **데이터 값 비교가 실행될 때마다 1회** 센다. 반복문 인덱스 검사(`j >= gap`, `i < n`)는 세지 않는다. 정렬 함수가 비교 횟수를 반환하고 `main.c`가 출력한다.
- 세 정렬 모두 끝난 뒤 오름차순 여부를 검사했고, 모든 경우에서 정상 정렬을 확인했다.
- 삽입 정렬은 간격이 1인 쉘 정렬 한 번과 같다. 세 알고리즘은 같은 함수(`gap_insertion_pass`)를 공유하며, 차이는 **간격 수열뿐**이다.
- 분석에 쓴 **패스별 비교 횟수**는 같은 데이터에서 `gap_insertion_pass`를 간격마다 따로 세어 얻었다. 패스별 합계는 본 측정 결과(n=20,000: 607,160 / 533,693)와 일치한다.

## 3. 데이터 크기 증가에 따른 비교 횟수 변화

| n | 삽입 / (n²/4) | 삽입 증가 배율 | 쉘(기본) 증가 배율 | 쉘(Knuth) 증가 배율 |
|---:|---:|---:|---:|---:|
| 1,000 | 0.99 | - | - | - |
| 2,000 | 1.02 | ×4.12 | ×2.35 | ×2.42 |
| 4,000 | 0.98 | ×3.85 | ×2.43 | ×2.29 |
| 8,000 | 0.99 | ×4.04 | ×2.35 | ×2.27 |
| 16,000 | 1.01 | ×4.05 | ×2.50 | ×2.45 |
| 20,000 | 1.00 | ×1.55 (n은 ×1.25) | ×1.19 | ×1.23 |

**삽입 정렬**은 n이 2배가 될 때 비교 횟수가 약 4배가 되고, n이 1.25배가 되면 1.55배(≈1.25²)가 된다. 비교 횟수가 n²에 비례한다. 실측값은 n²/4의 0.98~1.02배다. 삽입 정렬은 원소를 한 칸씩만 옮기기 때문에 비교 횟수가 배열의 역순 쌍(inversion) 수와 거의 같고, 무작위 배열의 역순 쌍 수는 평균 n(n−1)/4이기 때문이다.

**쉘 정렬**은 n이 2배가 될 때 약 2.3~2.5배(n^1.2~1.3)로, 삽입 정렬의 4배보다 훨씬 완만하다. 이유는 다음 두 가지로 설명된다.

1. 패스 수가 거의 log n으로만 늘어난다. 기본 간격은 n이 2배가 될 때 패스가 1개씩(9→10→11→12→13개), Knuth는 3배마다 1개씩 늘어난다 (n=1,000에서 6개, n=20,000에서 9개).
2. 마지막 패스(간격 1)의 비용이 n에 비례하는 수준으로 유지된다. 아래 표에서 쉘 정렬의 마지막 패스는 n이 2배가 될 때 약 2배(×1.95~2.06)가 된다. 삽입 정렬 전체가 ×4인 것과 대조적이다.

## 4. 삽입 정렬과 쉘 정렬의 성능 차이

n=1,000에서 쉘 정렬은 삽입 정렬보다 16~18배 적게 비교하지만, n=20,000에서는 164~187배 적게 비교한다. 데이터가 클수록 격차가 커지는 것은 앞 절의 증가율 차이(×4 대 ×2.4)가 누적되기 때문이다.

차이의 직접적인 원인은 **간격 1 패스에 들어가는 시점의 배열 상태**이다. 삽입 정렬은 무작위 상태의 배열에 곧바로 간격 1 패스를 수행하지만, 쉘 정렬은 앞선 큰 간격 패스들로 배열을 거의 정렬된 상태로 만든 뒤 간격 1 패스를 수행한다. 마지막 패스의 비교 횟수를 비교하면 다음과 같다.

| n | 삽입 정렬 전체 | 쉘(기본)의 마지막 패스 | 쉘(Knuth)의 마지막 패스 |
|---:|---:|---:|---:|
| 1,000 | 247,937 | 1,765 | 2,721 |
| 2,000 | 1,021,927 | 3,643 | 5,541 |
| 4,000 | 3,938,480 | 7,432 | 11,031 |
| 8,000 | 15,904,553 | 14,635 | 22,416 |
| 16,000 | 64,350,747 | 29,529 | 43,739 |
| 20,000 | 99,720,585 | 31,137 | 55,100 |

같은 간격 1 패스인데 n=20,000에서 삽입 정렬은 약 9,972만 회, 쉘 정렬은 3만~5.5만 회이다. 쉘 정렬의 마지막 패스는 원소 하나당 비교가 약 1.6~2.8회(≈n)로, 거의 정렬된 배열에서 삽입 정렬이 보이는 최선에 가까운 비용이다. 반면 삽입 정렬은 원소 하나당 비교가 약 4,986회이다. 쉘 정렬이 앞선 패스들에 쓴 비용(n=20,000에서 약 53만~58만 회)은 이 차이에 비해 매우 작다.

이것은 큰 간격 패스에서 원소 하나가 한 번에 멀리 이동하기 때문이다. 간격 g로 원소를 한 번 교환하면 사이에 있던 여러 역순 쌍이 한꺼번에 해소되는 반면, 삽입 정렬은 한 번 비교·이동할 때마다 최대 하나의 역순 쌍만 해소한다.

## 5. 쉘 정렬의 기본 간격과 Knuth 수열의 성능 차이

| n | 기본 간격 | Knuth | Knuth의 감소율 | 패스 수 (기본 / Knuth) |
|---:|---:|---:|---:|---:|
| 1,000 | 15,268 | 14,021 | 8.2% | 9 / 6 |
| 2,000 | 35,892 | 33,999 | 5.3% | 10 / 7 |
| 4,000 | 87,238 | 77,914 | 10.7% | 11 / 8 |
| 8,000 | 204,787 | 177,094 | 13.5% | 12 / 8 |
| 16,000 | 512,147 | 434,665 | 15.1% | 13 / 9 |
| 20,000 | 607,160 | 533,693 | 12.1% | 14 / 9 |

모든 크기에서 Knuth 간격이 5.3~15.1% 적게 비교했다. 감소율이 n에 따라 단조롭게 변하지는 않고, 크기마다 데이터 하나만 사용했으므로 몇 퍼센트 수준의 차이는 데이터에 따라 달라질 수 있다. 다만 6개 크기 모두에서 같은 방향이다.

원인을 n=20,000의 패스별 비교 횟수로 살펴본다. "최소"는 그 패스에서 반드시 필요한 비교 횟수 n−gap이다 (인덱스가 gap 이상인 모든 원소는 역순 쌍이 없어도 gap 앞의 원소와 한 번은 비교된다).

| 기본 간격 gap | 비교 | 최소 | | Knuth gap | 비교 | 최소 |
|---:|---:|---:|---|---:|---:|---:|
| 10000 | 10,000 | 10,000 | | 9841 | 10,384 | 10,159 |
| 5000 | 19,146 | 15,000 | | 3280 | 28,809 | 16,720 |
| 2500 | 25,326 | 17,500 | | 1093 | 42,930 | 18,907 |
| 1250 | 30,792 | 18,750 | | 364 | 53,975 | 19,636 |
| 625 | 37,171 | 19,375 | | 121 | 67,482 | 19,879 |
| 312 | **65,003** | 19,688 | | 40 | 82,891 | 19,960 |
| 156 | 38,424 | 19,844 | | 13 | 101,483 | 19,987 |
| 78 | 44,990 | 19,922 | | 4 | 90,639 | 19,996 |
| 39 | 50,023 | 19,961 | | 1 | 55,100 | 19,999 |
| 19 | **114,208** | 19,981 | | | | |
| 9 | **61,449** | 19,991 | | | | |
| 4 | 50,051 | 19,996 | | | | |
| 2 | 29,440 | 19,998 | | | | |
| 1 | 31,137 | 19,999 | | | | |
| **합계** | **607,160** | 260,005 | | **합계** | **533,693** | 165,243 |

1. **패스 수에 따른 고정 비용 차이**: 기본 간격은 14번, Knuth는 9번 패스한다. 패스마다 최소 비교가 약 n회씩 들기 때문에, 최소 비교의 합이 기본 260,005회, Knuth 165,243회로 94,762회 차이가 난다. 총 차이(73,467회)보다 큰 값이므로, **Knuth가 이기는 가장 큰 이유는 패스 수가 적다는 점**이다. 실제로 최소를 제외한 추가 비교는 n=20,000에서 오히려 Knuth가 더 많다 (기본 347,155 vs Knuth 368,450). Knuth는 간격이 3배씩 줄어 패스 하나가 더 많은 일을 하기 때문이다 (13, 4 간격 패스가 각각 약 10만, 9만 회).
2. **직전 간격이 홀수인 패스의 급증**: 기본 간격에서 비교 횟수가 유독 큰 패스(굵게 표시)는 모두 **직전 간격이 홀수**인 패스이다 (625→312, 39→19, 19→9). 예를 들어 gap 312는 인접한 패스(37,171, 38,424)의 약 1.7배, gap 19는 인접 패스(50,023, 61,449)의 약 1.9~2.3배이다. 이 패턴은 n=1,000~16,000에서도 같아서, 크기마다 비교 횟수가 가장 큰 세 패스는 모두 직전 간격이 홀수였다 (n=16,000: gap 62, 15, 7). 반대로 직전 간격이 짝수인 구간(10000→5000→2500→1250→625)은 비교 횟수가 완만하게 증가한다. Knuth는 이런 급증 없이 비용이 완만하게 늘었다가 줄어든다.
3. **n=16,000에서 차이가 가장 큰 이유**(15.1%): n=16,000은 기본 간격이 8000, 4000, 2000, 1000, 500, 250으로 여섯 번 연속 짝수이고, 이후 홀수 간격(125→62, 31→15)에서 두 번의 큰 급증(각각 92,583, 85,773회)이 발생한다. 이 비용은 최소 비교 차이(62,763회)만으로는 설명되지 않는 추가 차이(총 차이 77,482회)로 나타났다.

## 6. 간격 수열이 쉘 정렬의 성능에 영향을 미치는 이유

실험 결과에서 확인되는 원인을 정리한다.

1. **간격이 크게 줄어야 한다 (패스 수)**: 패스마다 최소 약 n회의 비교가 고정으로 든다. 간격을 절반씩 줄이면 n=20,000에서 14번, 3배씩 줄이면 9번이다. 고정 비용의 합이 260,005회와 165,243회로 갈렸고, 이것이 두 방식의 총 비교 횟수 차이를 만드는 가장 큰 요인이었다.
2. **마지막 패스가 거의 정렬된 배열에서 시작해야 한다**: 모든 간격 수열은 마지막에 간격 1을 쓰기 때문에, 그 이전 패스들이 배열을 얼마나 정렬해 두었는지가 성능을 좌우한다. 이 실험에서 이전 패스들이 마지막 패스 비용을 약 1억 회에서 3만~5.5만 회로 줄였다.
3. **간격이 서로 정렬 효과를 이어받는지**: 간격이 g에서 g/2로 정확히 절반이 되면, 이전 패스에서 정렬한 같은 묶음(인덱스를 g로 나눈 나머지가 같은 원소들)이 새 패스에서도 같은 묶음에 통째로 포함된다. 홀수 g에서는 g=2·g′+1이어서 이전 묶음이 새 묶음과 어긋난다. 실험에서는 후자의 패스에서 비교 횟수가 1.6~2.6배로 급증했다. 이 관찰은 실험 사실이고, "이전 패스의 정렬 정보가 덜 재활용되기 때문"이라는 설명은 이 사실에 대한 해석이다. Knuth 수열(1, 4, 13, 40, ...)은 3h+1 꼴이라 연속한 간격이 서로의 배수가 아니고 비용이 완만하게 분포한다.
4. **이론적 보장**: 이론적으로 기본 간격은 최악의 경우 O(n²), Knuth 수열은 O(n^1.5)이다. 이번 무작위 데이터에서는 기본 간격도 n^1.5를 넘지 않았다 (비교 횟수 / n^1.5 = 0.48 → 0.40 → 0.35 → 0.29 → 0.25 → 0.22로 감소). 그래서 두 수열의 실측 차이는 5~15%에 그쳤다. 최악 입력에서는 이 차이가 훨씬 크게 나타날 수 있지만, 이 실험에서는 확인하지 않았다.

## 7. 결론

- 삽입 정렬은 n²/4와 거의 일치하며 n이 2배가 되면 비교 횟수가 약 4배, 쉘 정렬은 약 2.4배가 된다.
- n=20,000에서 쉘 정렬은 삽입 정렬보다 164~187배 적게 비교한다. 원인은 간격 1 패스에 들어가기 전에 배열이 거의 정렬되어, 마지막 패스 비용이 약 1억 회에서 3만~5.5만 회로 줄기 때문이다.
- Knuth 간격은 모든 크기에서 기본 간격보다 5~15% 적게 비교했다. 주된 이유는 패스 수가 적어 패스마다 드는 고정 비용이 작다는 점이고, 기본 간격에서는 직전 간격이 홀수인 패스에서 비교가 급증하는 점도 영향을 준다.
- 크기마다 시드 하나로 한 번만 측정했으므로 정확한 퍼센트보다는 경향과 그 원인을 근거로 해석해야 한다.
